## Граница фальсификации

◐ Прямыми контрпримерами отвергнуты предположения «первые6карточек — весь
цифровой срез», «вся цифровая трансформация лежит в категории5», «историческое
жюри относится к текущему проректору», «агенты/безопасность/проектность
отсутствуют на рынке». Отдельно отвергнуты как **необоснованные выводы**
«пустое поле означает вакансию», «SQL устарел из-за ИИ», «релиз2022 описывает
текущий список ограничений»: они не следуют из названного evidence, что само
по себе не доказывает обратное.
Документальное сравнение не поддержало необходимость карты для генерации
новых тем; не установило улучшения решений и не проверяло H1.

○ Гипотезы спроса, переноса и экономики имеют проектные фальсификаторы в W6.
Они не опровергнуты и не подтверждены проведёнными пилотами: пилотов не было,
issue требует аналитические рекомендации, а не внедрение в чужую организацию.

## Воспроизводимая проверка

```bash
python3 experiments/issue-5/catalogue_probe.py --check experiments/issue-5/catalogue-2026-11-08.json
python3 experiments/issue-5/catalogue_probe.py --check experiments/issue-5/all-catalogue-2026-11-08.json
python3 -m unittest discover -s tests -p test_issue5_catalogue.py
./tools/validate-repository-structure.sh
python3 tools/validate_repo.py
python3 -m unittest discover -s tests
git diff --check
```

Живой повтор по необходимости: `catalogue_probe.py --output /tmp/digital.json`
и `--all --output /tmp/all.json`. Прочтение последовательное, максимум30страниц,
не более2MBнаответ; сохраняются только поля программ. Снимок фиксирует дату,
URL/next/count и SHA256 ответов, не копирует HTML с людьми. Raw-hash позволяет
сравнивать повтор, но не восстанавливает непубликуемый полный ответ.
Offline regression воспроизводит чтение полного JSON при незакрытом соединении:
до исправления1из3проверок падала, после исправления прошли3/3; четвёртая
проверка сопоставляет независимо полученные цифровой/общий снимки.
Проверки также отвергают неполный список и запрещённое поле.
Обязательные validators и общий unittest запуск фиксируются в commit/PR;
CI публичной ветки проверяется отдельно по SHA.
