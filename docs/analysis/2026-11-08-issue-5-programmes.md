# Цифровые программы: состав, актуальность, связность

## Вывод для руководителя

◐ В публичном предложении есть основания для двух траекторий: работа с
данными и прикладной ИИ. Ошибка — считать SQL устаревшим или предлагать
«добавить ИИ» как отсутствующую тему. Более предметная возможность — различить
пересекающиеся начальные курсы, определить входные требования и связать
учебный проект с проверкой применения после курса. Наличие отдельных
проектов и диагностики уже установлено; их отсутствие во всей академии
не утверждается. Источники и пределы — [реестр](2026-11-08-issue-5-evidence.md).
Пакет локальный до решения A2 о публикации.

○ **Связная корпоративная траектория**, которую можно проверить на имеющейся
базе: диагностика конкретной работы → P89/P120 только при дефиците базы →
выбор одной ветки (P94→P92→P93/P269 либо P343/P417/P380 по аудитории) →
кейс с рубрикой качества → применение в разрешённой среде → разбор через30дней.
P222 и P268 — альтернативы темпа, не обязательные ступени друг за другом.
P91/P239/P262 выбираются по результату «спецификация/отчёт/модель процесса»,
после проверки фактического перекрытия заданий. Формальный зачёт предмета,
правила допуска и расписание не выдумываются и не объявляются действующими.

◐ Международный контур B02/B03 и инфраструктура заказчика ограничивают перенос
стека. На пилоте — синтетические данные и предварительно разрешённые инструменты,
включая локальный вариант; доступность зарубежного сервиса не предполагается.
Для P417 проверяется возможность выполнить тот же результат без обязательного
внешнего агрегатора/конкретной IDE. Это требование к варианту пилота, не вывод
о незаконности или недоступности опубликованного курса.
