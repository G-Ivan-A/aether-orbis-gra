Исходное evidence доступно по
[закреплённой ссылке](https://github.com/konard/G-Ivan-A-mango_ba_prompts/blob/b98219e636427f06ba9bb8ebb4b94bddf912200a/experiments/issue_478/evidence.json).
Его SHA-256, путь и полный SHA находятся в `evidence.json → inherited`.
Для каждой исходной записи хеш считался так:
`sha256(json.dumps(record, ensure_ascii=False, sort_keys=True, separators=(',', ':')).encode())`.
Изменённые поля не считаются исходным текстом. Хеш сохраняет происхождение,
но не доказывает содержание удалённого URL или текущую должность.

Новые файлы RAEX и ответы сайта загружались в `/tmp` и не копируются сюда
полностью. Для N20 проверены тип PDF, 13 страниц, извлечённый текст;
размер и SHA оригинала — в N20. Использован локальный `pypdf 7.0.0` только
для чтения источника; проверкам репозитория он не требуется.
Даты неизвестных назначений/публикаций не восстановлены из дат индексации.

Проверки без сети (также запускаются через существующий unittest CI):

```bash
python3 experiments/issue-7/validate_evidence.py
python3 -m unittest discover -s tests -p 'test_issue7_evidence.py'
```

Отрицательные мутации проверяют пропавший locator/исходный ID, повышение
индексного имени, присвоение закупочного мандата, потерю live ID, изменённое
содержание JSON при ложном пустом списке изменений и изменение предшественника.
Положительный тест проверяет весь текущий пакет и валидность PNG.
Это применение проверок provenance из принятого протокола; новый стандарт
AI engineering здесь не создаётся.

Воспроизводимое получение комплекта и запуск браузера описаны в аудите.
Новый сетевой прогон создаёт новое наблюдение: при смене prod нельзя
переписывать старый отчёт так, будто он отражал новое состояние.
